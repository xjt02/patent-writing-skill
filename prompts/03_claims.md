# 03 — Claims（权利要求书）

> **阶段**：阶段 2
> **输入**：abstract_page.md + intake JSON
> **输出**：claims.json（结构化权利要求列表）

## 目标

从摘要中提炼权利要求书：1 条独立 + 3-5 条从属。

## 输出 Schema

```json
{
  "claims": [
    {
      "id": 1,
      "type": "independent",
      "text": "一种基于 XXX 的 YYY 方法，其特征在于，包括：步骤 1、...；步骤 2、..."
    },
    {
      "id": 2,
      "type": "dependent",
      "depends_on": 1,
      "text": "如权利要求 1 所述方法，其特征在于，..."
    }
  ]
}
```

## 硬约束

### 编号格式

| 类型 | 编号 | 开头句式 |
|---|---|---|
| 独立 | `1、一种 XXX 方法/系统/装置` | "其特征在于，包括：步骤 1、...；步骤 2、..." |
| 从属（引用前一条） | `2、如权利要求 1 所述...` | "其特征在于，..." |
| 从属（多项引用） | `5、如权利要求 1 或 2 所述...` | "其特征在于，..." |

### 数量约束

- 独立权利要求 = 1 条（**必须**）
- 从属权利要求 = 3-5 条
- 总数 ≤ 6 条（避免权利要求书过长）

### 内容约束

1. **渲染约束**（由 tools/md_to_docx.py 处理）：
   - 独立权利要求（id=1）：拆段处理。前导段 "1、一种XXX方法，其特征在于，包括以下步骤：" 顶格不缩进；后续每步 "步骤 N、<动作>；" 独立成段并首行缩进 2 字符。
   - 从属权利要求（id=2-5）：单段不缩进。
   - JSON 文本字段仍为单串（"步骤 1、...；步骤 2、...；..."），由渲染层按「；」+「步骤 N、」拆分。
2. **独立权利要求**必须包含方法的核心步骤
3. **从属权利要求**可细化步骤 1/步骤 2/步骤 3 的技术细节
4. 用词规范：
   - ✅ "其特征在于"
   - ✅ "进一步地"
   - ✅ "优选地"
   - ❌ 不用"特别地""值得注意的是"
   - ❌ 不用评价词（"极好""突破性"）
5. 不得在权利要求中提及具体实施例数字（如"约 5000 张"）
6. **独立权利要求必须用「步骤 N、」模板显式列出**：完整句式为
   `一种 XXX 方法/系统/装置，其特征在于，包括：步骤 1、<动作 A>；步骤 2、<动作 B>；...；步骤 N、<动作 N>。`
   其中 N = 方法的核心步骤数（推荐 3-5 步）。每步以「步骤 N、」+ 中文顿号「、」开头。
7. **从属权利要求用「步骤 N 所述的…」形式引用**：每条从属权利要求的特征部分首句必须是
   `步骤 N 中所述的 <技术特征> 包括：...` 或 `步骤 N 中所述的 <技术特征>，其中...`。
   不再使用「所述多源传感器数据」「所述特征提取」这种间接引用，必须显式绑定到具体步骤。
8. **步骤命名一律「步骤 N」**：权利要求书中所有步骤引用使用阿拉伯数字（1, 2, 3, ...），
   不用「步骤 S1」「步骤一」「Step 1」等其他形式。

### 依赖关系

- 从属权利要求**只能引用前面的权利要求**（id < 当前 id）
- 不能跨引用（如权利要求 5 不能引用权利要求 7）
- 多项从属引用时，写"如权利要求 X 或 Y 所述"

## 反例

- ❌ 独立权利要求 0 条或多条
- ❌ 从属权利要求引用了后续 id（id 5 引用 id 7）
- ❌ 评价词（"最优""完美")
- ❌ 超过 6 条
- ❌ 段首有缩进
- ❌ 独立权利要求漏写「步骤 N、」前缀（如直接写「采集设备振动...；对所述...」而无编号）
- ❌ 步骤命名用「步骤 S1/S2」或「步骤一/二」
- ❌ 从属权利要求用「所述多源传感器数据」这种间接引用，而不用「步骤 1 所述的」
- ❌ 段首有缩进（从属权利要求不允许；独立权利要求仅步骤段允许）
